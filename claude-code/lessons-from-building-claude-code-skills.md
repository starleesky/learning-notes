## 📌 核心观点

### Skills 的本质

**很多人（包括作者一开始）把 Skills 理解成「保存好的提示词」**——写个 SKILL.md，放进去，完事儿。

**但 Skills 的本质是文件夹，不是单个文本文件。**

```
my-skill/
├── SKILL.md          # 技能说明
├── assets/           # 模板、数据、参考文件
├── scripts/          # 可执行脚本
└── examples/         # 使用示例
```

Claude 可以发现、探索并操作这个文件夹里的所有内容。

**更强的是：** Claude Code 的 Skills 支持注册动态 hooks——你可以让 Skill 在特定事件触发时自动执行操作。

## 📊 Anthropic 内部 9 类 Skills

他们把内部几百个 Skills 做了一次系统梳理，发现大多数都能归入以下 9 类：

### 1️⃣ 库/工具使用教学

**用途：** 教 Claude 正确使用某个库、CLI 或 SDK。

不只是贴文档，而是包含真正有用的东西：
- 一个装满参考代码片段的文件夹
- 一份「踩坑清单」——告诉 Claude 写这个库时最容易犯哪些错

**示例：**
- `billing-lib` — 内部计费库的边界情况和 footgun 列表
- `internal-platform-cli` — 内部 CLI 全部子命令 + 使用场景示例
- `frontend-design` — 让 Claude 的输出对齐设计系统

**投入产出比：** 对于任何有内部库的团队，这类 Skill 的投入产出比极高。

---

### 2️⃣ 验证类 Skills

**用途：** 描述如何测试和验证代码是否正常工作。

这类 Skill 通常和 Playwright、tmux 等工具配合使用。

**验证类 Skill 直接影响 Claude 输出的质量。**

**建议：** 让一个工程师花整整一周专门打磨你的验证 Skill，这个投入是值得的。

**高级用法：**
- 让 Claude 录制输出的视频，这样你能直接看到它测试了什么
- 在流程的每一步强制插入断言，验证状态是否正确

---

### 3️⃣ 工作流自动化

**用途：** 自动化重复性工作流。

**示例：**
- 代码审查流程
- 部署流程
- 数据迁移流程

---

### 4️⃣ 领域知识注入

**用途：** 为 Claude 注入特定领域的专业知识。

**示例：**
- 医疗行业术语和规范
- 金融行业合规要求
- 法律文档格式标准

---

### 5️⃣ 代码风格规范

**用途：** 确保 Claude 输出的代码符合团队规范。

**示例：**
- 命名约定
- 注释规范
- 测试覆盖率要求

---

### 6️⃣ 调试辅助

**用途：** 帮助 Claude 更有效地调试问题。

**示例：**
- 常见错误模式清单
- 调试检查列表
- 日志分析指南

---

### 7️⃣ 安全审查

**用途：** 确保 Claude 的输出符合安全标准。

**示例：**
- 安全编码规范
- 常见漏洞清单
- 安全审查检查表

---

### 8️⃣ 性能优化

**用途：** 指导 Claude 优化代码性能。

**示例：**
- 性能基准测试
- 优化检查列表
- 常见性能陷阱

---

### 9️⃣ 文档生成

**用途：** 自动生成和维护文档。

**示例：**
- API 文档模板
- README 生成器
- 变更日志生成

## 🎯 关键洞察

### 洞察 1: Skills 是文件夹，不是文件

**错误理解：** Skills = 单个 SKILL.md 文件

**正确理解：** Skills = 文件夹结构 + 动态 hooks + 可探索内容

---

### 洞察 2: 验证类 Skill 值得重投入

**建议：** 让一个工程师花整整一周专门打磨验证 Skill

**回报：** 直接影响 Claude 输出的质量

---

### 洞察 3: 踩坑清单比文档更有价值

**不只是贴文档，而是包含：**
- 参考代码片段
- 「踩坑清单」——最容易犯哪些错
- 边界情况列表

---

## 💡 实践建议

### 建议 1: 从内部库开始

**优先级：** 为内部库/工具创建使用教学 Skill

**原因：** 投入产出比极高

---

### 建议 2: 投资验证类 Skills

**建议：** 安排专人花 1-2 周打磨验证 Skill

**工具：** Playwright, tmux, 视频录制

---

### 建议 3: 定期梳理 Skills

**建议：** 每季度梳理一次 Skills 分类

**目标：** 确保 Skills 归类清晰，易于发现和使用
